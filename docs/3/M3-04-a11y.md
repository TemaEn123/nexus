# М3.4 — a11y: Tab / DnD, live regions, axe-core

Имена из плана → код: Tab navigation для DnD = handle `Move card …` + `KeyboardSensor` (Space / Enter, стрелки, Escape) в `kanban-dnd.ts`; ARIA live regions = плагин `Accessibility` (`#dnd-kit-announcement-*`, `role="status"`) + `role="alert"` на ошибках; axe-core в CI = `@axe-core/playwright` в `e2e/`, GitHub Actions — М4.

## Шаг 0 — граница a11y

Клавиатура и анонсы DnD уже есть с М2.4 — не пилим второй канбан. Живой Chromium бьёт в живой Next + локальный Postgres, как M3.3. Хелперы те же: `registerUser`, `createBoard`, `addCard`, `columnByTitle`. jsdom / RTL / `vi.mock("@dnd-kit")` запрещены: нет геометрии колонок. Coverage % не цель — critical path с клавиатуры + WCAG A/AA на четырёх экранах.

| Слой | Мок | Что проверяем |
| --- | --- | --- |
| Клавиатурный DnD → `PATCH /api/cards/:id` | нет | фокус handle → Space → стрелки → drop → persist после reload; Escape без PATCH |
| Live region dnd-kit | нет | `role="status"` / `[id^="dnd-kit-announcement"]`: Picked up / over / Dropped / Cancelled — title карточки и колонки, не cuid |
| axe WCAG 2.0/2.1 A + AA | нет (сканер в браузере) | `/`, `/login`, `/dashboard` после register, доска с карточкой — settled DOM |
| Auth error как live | нет | неверный логин → баннер `role="alert"` («Invalid email or password.») |
| Postgres, Prisma, Auth.js, Route Handlers | нет | — |
| GitHub OAuth | нет, не тестируем | нужен реальный GitHub App |
| Vercel AI Gateway / Suggest 503 | нет | уже M3.3; axe не сканировать во время стрима |
| React Query Devtools / Next overlay | exclude в axe, не мок | чужой UI; в e2e не должен воровать Tab |
| Lighthouse / INP / CLS | нет | М3.5 |
| GitHub Actions, `playwright install chromium` | нет | М4 подхватит `pnpm test:e2e` |
| VoiceOver / NVDA как автотест | нет | ручной чеклист в отчёте |
| Drag колонок, gap-based, Storybook | нет | не в продукте |

«axe-core в CI» из плана = тесты, которые станут required check в М4, не workflow на этой неделе. `playwright.config.ts`: локально `pnpm dev` + `channel: "chrome"`; CI-заготовка `pnpm start` уже есть. Husky по-прежнему только lint + typecheck.

Теги axe: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`. Без `best-practice` и AAA. `disableRules` пачкой «чтобы зелёное» нельзя — exclude только Devtools и Next overlay. Скан не во время drag.

Анонсы DnD не через `getByRole("alert")`: Next route announcer тоже alert (M3.3). `dragover` у dnd-kit debounce 500ms. Пустая In Progress — целевой drop с клавиатуры (мышью это уже закрыто в critical path).

Не делать: `page.route` на PATCH, test-seam в `KeyboardSensor`, вынос `ColumnHeader` «для a11y», второй мышиный critical path.

БД: локальный Postgres (`127.0.0.1:5433`), не Neon. `AUTH_SECRET`, `nvm use 24`.

## Шаг 1 — разведка axe

Сделано:

- DevDep `@axe-core/playwright@4.13.0` (к Playwright 1.63). Зелёных axe-спек нет — только разведка
- Теги: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`. Exclude: `.tsqd-parent-container`, `nextjs-portal`. Скан не во время drag
- Четыре экрана, settled DOM: `/`, `/login`, `/dashboard` (register, «No boards yet»), доска Sprint + `Write e2e`

| Экран | violations | incomplete |
| --- | --- | --- |
| home | нет | нет |
| login | нет | нет |
| dashboard | нет | нет |
| board (сразу как виден handle) | `list` serious: `<ul>` колонки, дети `[role=button]` | `aria-allowed-attr` (`aria-grabbed` на handle и на `<li>`), `color-contrast` на `⋮⋮` |
| board (~1s после `aria-roledescription` на handle) | нет | `aria-grabbed` только на handle; `⋮⋮` — «only non-text characters» |

`list` — гонка dnd-kit: сначала `role="button"` на `<li>` (и клон с `aria-disabled` у `:root`), потом атрибуты остаются на handle. В шаге 4 ждать, пока в колонке нет `li[role=button]`, не `disableRules(['list'])`.

incomplete ≠ fail: `aria-grabbed` ставит dnd-kit (deprecated, не форкаем); контраст глифа axe не считает. Баннер логина без `role="alert"` сканер не ловит — это шаг 2, не axe.

React Query Devtools в этом прогоне **не** дал WCAG A/AA violations. Exclude всё равно: чужой UI и Tab. `nextjs-portal` не всплыл.

Проверка: scout 3 прогона, картина стабильная; `pnpm test:e2e` без scout-спека + `pnpm lint` + `pnpm typecheck`. Scout-файл не оставляем.

## Шаг 2 — точечный прод-фикс

Сделано:

- `LoginForm` / `RegisterForm`: баннер ошибки с `role="alert"`, как у board forms. Unit-тесты ищут `getByRole("alert")`
- Handle: `text-zinc-600` / `dark:text-zinc-400` (не `zinc-400` на белом). `focus-visible:outline` на ручке
- Инпуты с `outline-none`: то же кольцо `focus-visible` (auth, create/edit card, column, board) — Tab без невидимого фокуса
- Query Devtools только в обычном `pnpm dev`. Playwright `webServer.env.NEXT_PUBLIC_E2E=1` и production — без панели. `reuseExistingServer` со своим `pnpm dev` панель всё ещё покажет; клавиатурные спеки шага 5 фокусируют handle напрямую
- Offset клавиатуры не трогали: 10px vs `w-72` проверим в шаге 5, не наугад. `aria-grabbed` / гонка `list` — не форк dnd-kit

Не делали: skip-link, Suggesting live region, вынос fieldClass в общий модуль.

Проверка: unit auth (7) + e2e wrong password (`getByRole("alert")` + текст, не голый alert из‑за Next announcer) + `pnpm lint` + `pnpm typecheck`. Кольцо фокуса и контраст ручки глазами в headed-браузере не гоняли — нет browser MCP; шаг 5 Tab это закроет.
