# М4.3 — GitHub Actions: lint, typecheck, unit, E2E, preview

Имена из плана → код: задача 3 «PR + push to main; pnpm cache → Biome → typecheck → unit → E2E (Playwright, Chrome); Preview на Vercel для каждого PR». Файл: `.github/workflows/ci.yml`. Jobs `quality` и `e2e` (required checks — задача 4). Dependabot — задача 5.

## Шаг 0 — граница CI

Цель: пуш в `main` и каждый PR гоняют те же проверки, что локально (lint / typecheck / Vitest / Playwright), плюс preview URL от Vercel. Coverage % / CWV / Docker-сборка в Actions — не цель. Husky остаётся **только** lint + typecheck.

| Слой | Мок | Что делаем |
| --- | --- | --- |
| Trigger | нет | `pull_request` + `push` на `main` |
| pnpm cache | нет | `pnpm/action-setup` + `setup-node` `cache: pnpm`, Node 24, pnpm 11.21 |
| Job `quality` | нет | `pnpm lint` → `typecheck` → `test:run`. Без Postgres, без браузера |
| Job `e2e` | нет | service `postgres:16`, `migrate:deploy`, `pnpm build` **без** `DOCKER=1`, `pnpm start` |
| Браузер | нет | CI: Playwright **Chromium**. Хост: `channel: "chrome"` (РФ, как M3.3) |
| Preview Vercel | нет | GitHub App Vercel, не `vercel deploy` из GHA |
| Neon / live | нет | e2e только на Postgres в job. Прод/preview Vercel не трогаем workflow’ом |
| Branch protection | нет | задача 4; здесь только имена job |
| Dependabot / Renovate | нет | задача 5 |
| Docker compose в CI | нет | не в плане |
| Playwright / Lighthouse в Husky | нет | запрет с M3 |

Не делать: e2e против Neon, GitHub OAuth в Playwright, живой AI Gateway, `channel: "chrome"` на `ubuntu-latest` (нет системного Chrome), `DOCKER=1` на CI-build, деплой production из Actions, Redis, расширение Husky.

GHA крутится у GitHub, не из РФ: `playwright install --with-deps chromium` ок. Локальный бандл Chromium с GCS по-прежнему может рваться — конфиг: Chromium только если `CI`.

`< 3 мин` из Deep Dive — ориентир на **quality**. E2E (`next build` + браузер) часто 5–8 мин; hard fail нет.

Preview пишет в **тот же Neon**, что прод (уже в README). CI-миграции на Neon не гоняем. Credentials-e2e на GHA Postgres. GitHub login на `*.vercel.app` может быть `Configuration` — не блокер M4.3.

`pnpm-workspace.yaml` (`allowBuilds`) обязателен в checkout — pnpm 11, как Docker M4.1. `HUSKY=0` на install. Dummy `AUTH_SECRET` / `DATABASE_URL` в job `e2e`, не секреты прода.

`playwright.config.ts`: `CI === "true"` → `pnpm start --hostname 127.0.0.1`, `AI_GATEWAY_API_KEY=""`, retries 2. `channel: "chrome"` только без `CI`.

`nvm use 24` на хосте. Порты 3000/5433 и compose не меняем.

Порядок: граница → каркас workflow + cache → job `quality` → job `e2e` + Chromium → Preview Vercel → README → живой PR (этот шаг).

## Шаг 1 — каркас `ci.yml`

Сделано: `.github/workflows/ci.yml`.

- trigger: `push` на `main`, `pull_request`
- `concurrency` на ref, `cancel-in-progress`
- Node из `.nvmrc` (24.19.0), pnpm из `packageManager` (`pnpm/action-setup@v6` без `version`)
- кэш: `setup-node` `cache: pnpm` (action-setup **до** setup-node)
- `HUSKY=0` на job env — `prepare` не ставит хуки
- job `quality`: checkout → install `--frozen-lockfile` → `pnpm lint`

Ещё нет: `typecheck` / `test:run` (шаг 2), `e2e`, Chromium, Preview.

Проверка на этом шаге: YAML в репо. Живой прогон GHA — после push (шаг 6). `actionlint` не гоняли.

## Шаг 2 — `quality`: typecheck и unit

Сделано: после lint — `pnpm typecheck`, `pnpm test:run`. Не `pnpm test` (watch). Postgres / Playwright в этом job нет.

`DATABASE_URL` dummy в `env` workflow: `prisma generate` в `postinstall` зовёт `env("DATABASE_URL")` из `prisma.config.ts`. К серверу quality не коннектится. Тот же URL позже совпадёт с GHA Postgres на 5432 (не хостовый 5433).

Timeout job 15 мин (typegen + Vitest на холодном кэше).

Не делали: job `e2e`, `channel` Chromium, секреты прода, расширение Husky.

## Шаг 3 — job `e2e`

Сделано: параллельный job `e2e` (не depends on `quality`).

- service `postgres:16`, user/db `nexus`, порт **5432** (не хостовый 5433)
- `DATABASE_URL` тот же dummy из workflow env, теперь живой
- `AUTH_SECRET` только в e2e, не секрет прода. `NEXT_PUBLIC_APP_URL=http://127.0.0.1:3000`
- `pnpm db:migrate:deploy` → `pnpm build` **без** `DOCKER=1` → `playwright install --with-deps chromium` → `pnpm test:e2e`
- GHA сам ставит `CI=true` → webServer `pnpm start`
- при фейле артефакт `playwright-report/` + `test-results/` (7 дней)

`playwright.config.ts`: `channel: "chrome"` только если нет `CI`. На CI — бандл Chromium. Reporter на CI: list + html.

Не делали: Neon, compose, GitHub OAuth, живой Gateway, Husky, Preview YAML.

## Шаг 4 — Preview Vercel, не GHA

Сделано в политике, не в YAML: деплой preview — **Vercel GitHub App**, как production. В `ci.yml` нет `vercel deploy`, нет `VERCEL_TOKEN`, нет job с preview URL.

Прод уже: [nexus-pi-amber-56.vercel.app](https://nexus-pi-amber-56.vercel.app), Build `pnpm db:migrate:deploy && pnpm build`. README: Preview пишет в **тот же Neon**.

Что не кладём в Actions (дубль деплоя, секреты Vercel в GHA):

- `amondnet/vercel-action` / `vercel pull && vercel deploy`
- production deploy из workflow

Проверка глазами в Vercel (проект Nexus → Settings → Git / Deployments):

- репозиторий `TemaEn123/Nexus` подключён
- Preview Deployments для PR **включены** (дефолт Hobby)
- Ignored Build Step не глушит PR
- бот **vercel** комментирует PR после пуша ветки (живой URL — шаг 6, когда будет PR)

GitHub OAuth: production callback ≠ `*.vercel.app`. Вход через GitHub на preview может быть `?error=Configuration`. Credentials на preview работают. Не блокер: e2e Credentials на GHA Postgres, не на Vercel.

Не делали: третье OAuth App «на все preview», отдельная ветка Neon, секреты Vercel в GitHub.
