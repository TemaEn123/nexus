## Шаг 1 — Kanban API

Текст, чтобы проговорить. Код не менялся.

Доска принадлежит одному пользователю: у `Board` есть `ownerId`, у колонки и карточки своего владельца нет. Колонка смотрит на доску, карточка — на колонку. Удаление доски каскадом снимает колонки и карточки. Позиция уникальна внутри доски у колонок и внутри колонки у карточек.

Сессия — Auth.js, JWT. На REST нет сессии → 401 JSON `{ error }`. Редирект на `/login` для API не использую: клиент ждёт JSON. Proxy на `/api` не вешаю, иначе callback GitHub тоже поймал бы редирект. Чужая или несуществующая доска — 404, не 403: по ответу не видно, что доска есть у другого человека. Проверка одна, в `service.ts`: `Board.ownerId === userId`, колонка и карточка через эту связь.

Контракт: успех `{ data }`, ошибка `{ error: { code, message } }`. Тело проверяет Zod до сервиса.

Ручки:

- `GET /api/boards` и `POST /api/boards` — список и создание
- `GET`, `PATCH`, `DELETE /api/boards/[boardId]`
- `POST /api/boards/[boardId]/columns`, `PATCH` и `DELETE` колонки
- `POST` карточки в колонку, `PATCH` и `DELETE /api/cards/[cardId]`

Создание доски — одна транзакция: доска, три колонки To Do / In Progress / Done и запись в `activityLog`. Формы дашборда зовут те же функции сервиса через Server Actions. Перенос карточки — `PATCH`: `columnId` и `position`. Занятый слот сдвигается, ответ 200. `columnId` с чужой доски — 404.

Список своих досок сейчас целиком, сортировка `updatedAt` по убыванию, индекс по `ownerId` уже есть. Если досок станет много, отдам курсор парой `(updatedAt, id)` и limit, без offset.

## Шаг 2 — две вкладки

Текст, чтобы проговорить. Код не менялся.

Карточка на экране — это кэш TanStack Query. Пока форма сохранения ещё летит, поверх кэша лежит `useOptimistic`: заголовок и описание меняются сразу, колонки в этот overlay не входят. Жест переноса держит порядок в локальном state и в `onMutate` пишет снимок кэша. Сервер ответил успехом — в кэш кладём карточку из ответа. Ошибка — overlay React снимает сам, перенос возвращает снимок. Вторая вкладка этот кэш не видит: общего канала нет.

На сервере гонка слота позиции закрыта. Перенос берёт `SELECT … FOR UPDATE` по строке доски, заново читает колонку и позицию и сдвигает соседей в той же транзакции. Уникальный слот, который всё же столкнулся, — 409 `conflict`. На экране текст «Someone else updated the board. Try again.»

Правка текста так не защищена. `updateCard` не сравнивает `updatedAt`. Две вкладки сохраняют заголовок — обе получают 200, в базе остаётся тот, кто записал последним. Клиент не шлёт версию, которую рисовал.

Если PATCH уже не про ту версию, я бы не оставлял на экране несохранённый текст как будто он в базе. Клиент шлёт `updatedAt`, который был на карточке. Сервер обновляет строку только при совпадении. Ноль строк — 409. Форма показывает ту же фразу про чужое обновление, overlay откатывается, доска заново читается с сервера, и человек видит чужой заголовок.

## Шаг 3 — совместная доска

Текст, чтобы проговорить. Код не менялся, пакет для сокетов не ставился.

Сейчас вторая вкладка узнаёт о чужом сохранении только когда сама снова читает доску. Запись уже есть: формы через Server Actions, перенос через `PATCH /api/cards/[cardId]`. Эти запросы и остаются способом изменить карточку.

Для «карточка у соседа уехала в Done» хватает потока сервер → браузер. Это SSE: одно соединение `GET`, события текстом. Клиенту не нужно слать перенос внутрь того же канала. WebSocket я бы взял, когда на доске появятся чужой курсор и присутствие «кто сейчас смотрит»: там сообщения идут в обе стороны и часто.

Поток сел бы рядом с текущим API: `GET /api/boards/[boardId]/stream`. Та же проверка, что у остальных ручек: сессия и `ownerId`. После успешной транзакции в сервисе уходит сигнал «доска изменилась», в теле — `boardId`. Браузер на этом сигнале делает `invalidateQueries` по `boardKeys.detail` и забирает доску тем же чтением, что и сейчас. В событии нет копии всей доски: источник карточек — Postgres.

Подписчиков в памяти одного процесса мало. На Vercel изолятов много, карта в памяти одного из них чужие вкладки не найдёт. Сигнал между процессами — `LISTEN/NOTIFY` самого Postgres, без Redis и без нового пакета. Соединение SSE хочет процесс, который не засыпает после ответа. Пока приложение живёт serverless-функцией, запись остаётся на Vercel, а поток — у процесса рядом с базой. До этого вторая вкладка по-прежнему обновляется своим следующим чтением.

## Шаг 4 — пять задач

Условия для репетиции на 25 минут. Решения в `src/` не лежат.

### 1. Поиск карточек с debounce

На доске уже есть карточки в кэше `useBoardQuery`. Нужно поле: человек печатает, список карточек сужается по заголовку. Запрос на каждый символ не уходит. Пустая строка снова показывает всю доску.

С чего начать: `use-board-query.ts` и колонки в `kanban-board.tsx`. Фильтр по уже загруженным карточкам, отдельный search-API не нужен.

Готово: пауза около 300 мс после последнего символа, регистр не важен, пока пауза не вышла — на экране прежний список.

### 2. Хук доски

Перенос уже живёт в `useMoveCardMutation` и в `KanbanBoard`. Нужен один хук, который отдаёт колонки и обработчик конца жеста. Компонент доски не собирает снимок кэша сам.

С чего начать: `use-move-card.ts` и `kanban-board.tsx`. `PATCH` и откат снимка остаются.

Готово: доска вызывает хук, карточка после дропа уезжает тем же `PATCH`, ошибка возвращает порядок до жеста.

### 3. Лента activity

`ActivityLog` пишется в транзакциях сервиса. Ручки «прочитать ленту» нет. Индексы по `boardId` есть. Нужна страница событий доски и подгрузка следующей, когда низ списка виден.

С чего начать: модель `ActivityLog` и `GET /api/boards/[boardId]`. Та же проверка владельца. Курсор — пара `(createdAt, id)`, страница 20. Черновик ручки в этот репозиторий не коммитить.

Готово: первая страница приходит сразу, вторая — когда sentinel в зоне видимости, повторный запрос той же страницы не дублирует строки.

### 4. Модалка

Отдельного диалога нет, правка карточки — форма внутри карточки. Нужна модалка подтверждения удаления: фокус остаётся внутри, Escape закрывает.

С чего начать: `delete-card-form.tsx`. Разметка — `role="dialog"` и `aria-modal`.

Готово: открытие переносит фокус на кнопку внутри, Tab и Shift+Tab ходят только по ней и отмене, Escape закрывает, фокус возвращается на кнопку, которая открыла окно.

### 5. `useLocalStorage`

Нужен хук: значение живёт в state и в `localStorage`. Для репетиции достаточно последнего открытого `boardId`.

С чего начать: пустой хук рядом с черновиком, не в `src/`. Ключ строкой, значение через `JSON.parse`.

Готово: после перезагрузки страницы значение на месте. Вторая вкладка того же origin получает новое значение через `storage`. Битый JSON не роняет хук: остаётся начальное значение.

## Шаг 5 — питч

Текст на две минуты. Код не менялся. Сложный кусок — оптимистичная доска. Стрим Suggest — одна фраза, чтобы не увести разговор во вторую историю.

Nexus — канбан, который можно открыть по ссылке: https://nexus-pi-amber-56.vercel.app. Человек регистрируется или входит через GitHub, заводит доску и перетаскивает карточки между To Do, In Progress и Done. У карточки есть подсказки: сервер стримит их из Groq, ключ в браузер не попадает.

Стек одной фразой: Next.js App Router, Postgres с Prisma, сессия Auth.js, кэш доски в TanStack Query.

Доска принадлежит одному пользователю. Чужая доска для API выглядит как отсутствующая: 404, не «доступ запрещён». Список, создание и перенос идут через один сервис. Формы зовут его Server Actions, перетаскивание — через PATCH.

Сложный кусок — перенос карточки. Пока запрос ещё летит, колонка на экране уже в новом порядке. Это снимок кэша, не вторая копия доски в другом стейте. Сервер в это время блокирует строку доски, заново читает позицию и сдвигает соседей. Если ответ с ошибкой, экран возвращает снимок. Вторая вкладка этот кэш не видит: общего канала нет, источник карточек — Postgres.
