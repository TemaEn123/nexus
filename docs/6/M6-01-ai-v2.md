# М6.1 — AI v2: контекст доски

Имена из плана → код: задача 1 «AI v2: контекстный ассистент (знает board state) — Break down this epic, Suggest priority». Groq (`GROQ_API_KEY`, `@ai-sdk/groq`) и `@/features/ai-assistant`. Клиент по-прежнему шлёт только id; снимок доски — с сервера из БД. Стрим UX (typing / abort polish) — задача 2 М6. Чат свободным текстом — не этот шаг.

## Шаг 0 — граница

Цель: модель видит **колонки и названия карточек**, не одну карточку. Suggest subtasks не дублирует то, что уже на доске. Suggest priority — какую карточку делать дальше и почему. Coverage / CWV / смена модели / таблица Subtask — не цель.

Сейчас (М2.9): `POST /api/cards/:cardId/suggest` — `getOwnedCard`, промпт = title + description этой карточки. Кнопка Suggest subtasks на карточке. Add — обычная карточка в ту же колонку. Доска в промпт не попадает.

| Слой | Мок | Что делаем |
| --- | --- | --- |
| Снимок доски | нет | `boardSnapshot` из `getBoard`; title доски, колонки, title карточек |
| Источник state | нет | БД после `requireApiUser`; не body, не TanStack cache |
| Break down | нет | тот же `POST /api/cards/:id/suggest`, промпт + снимок |
| Suggest priority | нет | `POST /api/boards/:boardId/priority`; кнопка в header доски |
| Список в промпте | нет | `[1] To Do: Login` — индекс, не UUID |
| Ответ priority | нет | `{ pick: number, reason }` → UI подсвечивает карточку |
| Ответ subtasks | нет | схема 3–7 title как М2.9; Add в ту же колонку |
| Few-shot | нет | в instructions: не повторять title с доски |
| Потолок снимка | нет | обрезка длинных title, ~40 карточек |
| Descriptions всех карт | нет | в снимок не кладём (токены + injection) |
| Чат / свободный prompt | нет | две команды, не textarea |
| Таблица Subtask | нет | Add = `createCardAction`, как М2.9 |
| Streaming UX | нет | задача 2; `useObject` / Suggesting… / Stop как есть |
| Модель / Gateway | нет | не меняем |
| Rate limit / sanitize М5 | нет | не ломаем; новый route — те же 401 / 404 / 503 |
| Живая LLM в CI | нет | юнит-тесты промпта на фикстуре |
| `ci.yml` / Husky / Ruleset | нет | не меняем |

Не делать: клиент присылает board JSON; сырой Prisma в промпт; чат; двигать карточку из priority; Add all; смена провайдера; e2e против модели; Redis.

Почему не чат: две кнопки дешевле, контракт Zod жёсткий, на собесе ясно «context = snapshot, не dump». Почему индексы: модель не выдумает `cardId`.

Не ломаем: ключ только сервер, body suggest пустой, 404 на чужой id, UI без ключа жив (503 `unavailable`).

Порядок: граница → `boardSnapshot` + тесты (этот шаг) → break down с контекстом → route + UI priority → проверка на доске → README.

Проверка шага 0: этот файл. Кода и новых route нет.

## Шаг 1 — `boardSnapshot`

Сделано: `src/features/ai-assistant/board-snapshot.ts`. Вход — `{ title, columns: { title, cards: { title }[] }[] }` (и `BoardDetail`, и Prisma-строка).

- `[1] To Do: Login` — порядок колонок, затем карточек; индекс, не UUID
- title обрезается до 80; пустой → `Untitled`
- пустая доска: `Board: …\n(no cards)`
- потолок 40 карточек + строка `(+N omitted)`
- description и id в текст не попадают

Тесты: `board-snapshot.test.ts` на `makeBoard`. Route / промпт suggest не трогали.

## Шаг 2 — break down с контекстом

Сделано: тот же `POST /api/cards/:cardId/suggest`. После `getOwnedCard` — `getBoard` по `card.column.boardId`. Промпт = `boardSnapshot` + `Target card` (title / description этой карточки). Instructions: не копировать title из списка, few-shot Login / OAuth. Схема 3–7, body пустой, UI карточки не трогали.

Тесты: `prompt.test.ts` на `makeBoard` (снимок в тексте, пустая доска, description соседа и id не попадают, instructions про повтор). Живую LLM не дергали.

## Шаг 3 — Suggest priority (API)

Сделано: `POST /api/boards/:boardId/priority`. Как suggest: `requireApiUser` → ключ → `parseIdParam` → `getBoard`. Body не читаем. Схема `{ pick: 1…40, reason: 1–200 }`. Промпт = снимок + «Which card should be next?». Instructions: индекс из списка, не UUID; To Do / In Progress раньше Done; few-shot Login. Пустая доска → 400 `validation_error`, модель не зовём. Карточки не двигаем. UI header — шаг 4.

Тесты: схема, `suggestPriorityPrompt` на `makeBoard`, `boardCardCount`. Живую LLM не дергали.

## Шаг 4 — Suggest priority (UI)

Сделано: кнопка **Suggest priority** над колонками (`KanbanBoard`). `useObject` → `POST /api/boards/:id/priority`, body `{}`. Пустая доска — disabled. Suggesting… / Stop / ошибка как у subtasks (`priorityError`: 401 / 404 / 503 / пустая доска). `reason` — `role="status"`. `pick` → `cardIdAtPick` по Query-доске (не optimistic): кольцо на карточке, `aria-current`. Карточки не двигаем.

Тесты: `cardIdAtPick`, `priorityError`, кнопка disabled / Stop. Живую LLM не дергали.

## Шаг 5 — проверка на доске

Локально, `localhost:3000`, ключ в `.env` есть. Пустая доска: **Suggest priority** disabled. Карточки Auth / Login / Payments: кнопка живая → Suggesting… / Stop. Network: `POST /api/boards/:id/priority` и `POST /api/cards/:id/suggest` (не api.openai.com с клиента). Карточки не сдвинулись. Ошибка инлайн, без сырого JSON: «Something went wrong. Try again.»

Стрим до модели на Gateway не дошёл (`403 customer_verification_required`). AI снова Groq (`GROQ_API_KEY`), как на hardening-production.
