# Месяц 2 — что мы сделали и зачем именно этот стек

Это человеческий отчёт по полностью закрытому шагу 2. Технические детали по подшагам лежат рядом: `M2-01` … `M2-09`. Здесь — картина целиком: что появилось в продукте, какие технологии это держат и почему выбрали именно их, а не соседние варианты.

---

## Одной фразой

Месяц 1 дал фундамент: вход, база, API, деплой. Месяц 2 превратил это в живую канбан-доску: колонки и карточки, перетаскивание, мгновенный интерфейс, нормальная загрузка страницы и кнопка «предложи подзадачи» от модели.

К концу шага залогиненный человек может создать доску, наполнить её колонками и карточками, переставить карточки мышью или с клавиатуры, править текст, удалять сущности и попросить ИИ набросать шаги по карточке. Аноним по-прежнему уходит на логин.

---

## Что появилось у пользователя

**Список досок.** На `/dashboard` видно свои доски, можно создать новую и удалить существующую с подтверждением. Пустой список говорит «досок пока нет», а не показывает дыру.

**Сама доска.** Открывается на всю ширину. Колонки стоят в ряд и на узком экране не стопкой, а со горизонтальным скроллом — как настоящий канбан, а не как мобильное меню. Внутри колонки — карточки, «добавить карточку», удаление колонки целиком.

**Карточки.** Создание, правка заголовка и описания, удаление. Пока жест или сохранение ещё не закончились, интерфейс уже показывает результат; если сервер отказал — откатывается.

**Перетаскивание.** Карточку можно переставить внутри колонки или перенести в другую, в том числе в пустую. То же самое с клавиатуры: Tab, пробел, стрелки, Escape. Экранный читатель слышит названия, а не внутренние id.

**Ожидание без «белого экрана».** Заголовок и форма создания доски приходят сразу, список — чуть позже со скелетом. На странице доски кнопка «назад» не ждёт карточки; колонки сначала рисуются скелетом.

**ИИ.** У карточки есть «Suggest subtasks». Модель стримит 3–7 коротких шагов на языке заголовка. «Add» превращает пункт в обычную карточку в той же колонке. Отдельной сущности «подзадача» нет — это сознательный MVP.

## Как мы к этому пришли (девять подшагов)

1. **Дашборд.** Список досок, создание и удаление через Server Actions. Страница конкретной доски пока заглушка, но уже защищена: чужой id даёт 404, не 403 (чтобы не светить, что доска существует).
2. **Канбан на экране.** Колонки и карточки из одного запроса `getBoard`, формы добавления, подтверждение удаления. Порядок колонок на любой ширине — ряд со скроллом.
3. **Порядок как инвариант базы.** У колонки уникальна позиция внутри доски, у карточки — внутри колонки. Перестановка — одна транзакция со сдвигом соседей. Гонка двух созданий не взрывает сервер 500, а отдаёт 409.
4. **Drag-and-drop.** Остров интерактива на клиенте: мышь, тач, клавиатура. На drop уходит целевой индекс, а не «сырой слот» — арифметику слотов клиент не дублирует.
5. **Кэш доски на клиенте.** TanStack Query: открыли доску — данные уже гидратированы с сервера, лишний GET не нужен. Перемещение карточки — оптимистично, ошибка — откат.
6. **Мгновенные create / edit / delete карточки.** Server Actions плюс `useOptimistic`. Редирект после мутации убрали: иначе оптимистичный слой бессмысленен. Колонки по-прежнему через Query.
7. **React Compiler всерьёз, не флажком.** Проверили, что компилятор реально мемоизирует канбан. Ручные `useMemo` / `useCallback` не добавляли «для вида».
8. **Стриминг страницы.** Границы Suspense расставили так, чтобы тяжёлая Prisma не блокировала шапку и кнопку «назад». Один скелет колонок переиспользуется в трёх местах.
9. **ИИ-MVP.** Route Handler как прокси к модели: ключ только на сервере, клиент шлёт лишь `cardId`, текст для промпта берётся из базы.

Намеренно не делали в этом месяце: Zustand, React Hook Form, shadcn, тесты, перетаскивание колонок, дробные «дыры» в позициях (1000 / 2000 / 3000), отдельную таблицу подзадач, чат по доске. Это не забыли — отложили, чтобы сначала закрыть канбан и историю про состояние.

## Технологии: что взяли, что это дало, почему именно они

Ниже — только то, чем реально пользовались в месяце 2. Стек месяца 1 (Next.js, Prisma, Postgres, Auth.js, Zod, Tailwind, Biome) никуда не делся: на нём всё стоит.

### Next.js App Router и React Server Components

**Зачем в принципе.** Канбан — не одностраничник в вакууме: нужна сессия, права, данные с сервера, нормальные URL. App Router даёт страницы, layouts, metadata и серверные компоненты из коробки.

**Что дали именно RSC.** Список досок и каркас страницы доски рендерятся на сервере. Prisma и проверка «это твоя доска?» не уезжают в браузер. Клиенту достаётся HTML плюс маленький остров канбана, а не вся логика приложения.

**Почему не «всё клиент».** Если бы дашборд сразу качал JSON и рисовал себя сам, первый экран ждал бы и JS, и запрос. RSC отдаёт заголовок и форму, пока список ещё грузится. `"use client"` ставили точечно: канбан, DnD, Query, формы с оптимистичным UI.

### Server Actions

**Что это.** Функции на сервере, которые форма или клиент вызывает напрямую, без ручного `fetch` на REST.

**Что дали.** Создание/удаление досок, колонок (часть потока) и весь CUD карточек: валидация Zod → сервис → Prisma. После успеха — `revalidatePath`, страница остаётся на доске. Ошибки карточек — инлайн, не через `?error=` в URL.

**Почему не только REST.** REST из месяца 1 жив: им пользуется DnD (`PATCH` карточки) и будущие тесты. Actions удобнее там, где мутация привязана к форме и сессии: нет отдельного клиента, ключи и Prisma остаются на сервере. Для стрима ИИ Actions не подошли — поэтому suggest пошёл в Route Handler.

### Prisma + PostgreSQL и уникальный `position`

**Что дали.** Колонки и карточки с порядком, который база умеет защищать. Unique на `(boardId, position)` и `(columnId, position)` — два элемента не могут занять одно место. Перестановка: транзакция, сдвиг соседей, после удаления — уплотнение `0…n−1`. Создание по-прежнему `max+1`, но в начале транзакции доска блокируется (`FOR UPDATE`), чтобы два параллельных create не столкнулись.

**Почему unique, а не «просто сортировать в UI».** Без ограничения в базе гонка двух запросов даёт дубли позиций. Тогда DnD рано или поздно ловит нарушение unique или едет порядок. Unique + 409 — второй слой защиты, не замена сдвигу: занятый целевой индекс при move сдвигает соседей и отвечает 200, не ошибкой.

**Почему не gap-based (1000, 2000, 3000).** Это быстрее на запись (меньше сдвигов), но сложнее и легче «поплыть» при уплотнении. Для учебного канбана важнее понятный инвариант: позиция — плотный индекс. Дыры в числах — осознанный долг на потом.

Локально в месяце 2 появился Postgres в Docker (`nexus-pg` на порту 5433): Neon из части сетей недоступен. Прод на Vercel по-прежнему ходит в Neon.

### Zod

**Что дал.** Один контракт на входе: пустой заголовок не доходит до базы, дробный/отрицательный `position` — 400, тело create не содержит `position` (его считает сервис). Типы для TypeScript выводятся из схем, а не дублируются руками.

**Почему не «проверить в компоненте».** Клиентский Zod отсекает очевидное до запроса (нет призрачной карточки с пустым названием). Серверный Zod — источник правды: клиент можно обойти. Prisma проверяет форму данных в базе, Zod — смысл запроса.

### @dnd-kit (актуальный пакет `@dnd-kit/react`, не legacy `core`)

**Что дал.** Перестановка и перенос карточек, сенсоры мыши и тача, клавиатурный режим, объявления для скринридера. Пустая колонка остаётся зоной сброса. Кнопки и поля не начинают drag случайно.

**Почему именно эта библиотека.** Это де-факто стандарт DnD в React: доступность из коробки, сортировка в списках, группы (колонки). Писать жесты с нуля — месяцы на баги тача и клавиатуры. HTML5 Drag and Drop API плохо дружит с тачем и a11y.

**Почему не перетаскивали колонки.** Сначала стабильный порядок карточек и unique в базе. Drag колонок — отдельный жест и отдельный инвариант `(boardId, position)`.

### TanStack Query

**Что дал.** Кэш доски на клиенте, гидратация с RSC (открыли страницу — повторный GET не нужен), оптимистичный move с откатом, инвалидация после ответа сервера. Пока палец на карточке, случайный refetch с фокуса окна не перетирает жест.

**Почему не «просто useState + fetch».** Канбан живёт долго: фокус окна, повторный заход, ошибка сети, параллельные мутации. Query даёт снимок «как было», откат и согласованные ключи кэша. Список досок на `/dashboard` специально оставили на RSC + Actions — Query там пока лишний.

**Почему не Zustand для данных доски.** План обучения держал Zustand для эфемерного UI. Данные с сервера в два стора сразу — классическая ловушка: кто источник правды после refetch? Правило месяца: Query = колонки и карточки; превью жеста = локальный `useState`; Zustand не подключали, пока не появился отдельный UI-слой (сайдбар, фильтры), которому он реально нужен.

### `useOptimistic` (React 19)

**Что дал.** Добавление, правка и удаление карточки видны сразу, до ответа сервера. Временный id, потом настоящий cuid. Пока карточка «временная» — drag и delete выключены, чтобы не двигать то, чего в базе ещё нет.

**Почему рядом с Query, а не вместо.** Query отлично закрывает move: там уже есть REST `PATCH` и `onMutate`. CUD карточки удобнее как формы + Actions. `useOptimistic` сидит поверх кэша Query: после успеха кэш обновляют сначала (`cuid`, новый текст, без карточки), потом refetch — иначе оверлей откатится на старую доску.

**Почему не `redirect` после create.** Редирект размонтирует дерево и убивает оптимистичный слой. Actions карточек возвращают `{ ok, card? }` или код ошибки.

### React 19 Compiler

**Что дал.** Автоматическая мемоизация канбана. В бандле доски есть runtime компилятора — это не мёртвый флаг в конфиге. В `src` нет ручных `useMemo` / `useCallback` / `React.memo`.

**Почему не обкладывать всё `useCallback`.** Компилятор как раз чтобы не делать это ритуалом. Обёртки оставили только как правило на потом: зависимости эффекта, чужой API который сравнивает по ссылке (dnd-kit плагины — один экземпляр через `useState(init)`), или профайлер показал реальную проблему.

### Suspense и streaming

**Что дали.** Страница не ждёт самый медленный кусок. Дашборд: шапка и форма сразу, список — скелет. Доска: «назад» сразу, заголовок и канбан — своими скелетами. `requireUser` обёрнут в `cache()`, чтобы меню, список и загрузка доски не ходили в `auth()` трижды за один запрос.

**Почему не N запросов «по колонке».** `getBoard` — один Prisma `include`. Дробить на колонки — водопад в другую сторону и хуже гидратация Query. PPR / `cacheComponents` не включали: сначала понятные границы Suspense.

**Почему нет `dashboard/loading.tsx`.** Родительский `loading` мигал бы и на странице конкретной доски. Список и доска получили свои скелеты точечно.

### Vercel AI SDK 7 + Route Handler

**Что дали.** Стрим объекта `{ subtasks: { title }[] }`, кнопка Stop, пункты дорисовываются по мере ответа. Клиент бьёт в свой `/api/cards/:id/suggest`, не в OpenAI напрямую. Ключ `AI_GATEWAY_API_KEY` только серверный. Без ключа UI живой: кнопка есть, ответ — 503 «недоступно».

**Почему SDK, а не сырой fetch к модели.** Стрим, схема выхода, React-хук `useObject`, обрыв запроса — это готовый контракт, а не самописный парсер чанков.

**Почему Route Handler, а не Server Action.** Стрим LLM через Action — плохой паттерн; ключ не должен оказаться в бандле. Handler: сессия → ключ → «карточка твоя?» → стрим. Title и description для промпта читаются из базы, не из тела запроса — клиент не подменяет контекст.

**Почему нет таблицы Subtask.** MVP: список в памяти, «Add» создаёт обычную карточку тем же optimistic-путём, что и ручная форма. Отдельная сущность и чат по доске — позже (месяц 6 в плане).

**Почему `gpt-4o-mini` через Gateway.** Достаточно для коротких шагов, дешевле флагманских моделей, ключ один (Gateway), без отдельного `@ai-sdk/openai` в зависимостях.

## Как устроено состояние — коротко

Это главная архитектурная история месяца, её можно рассказывать на собесе.

| Что храним | Где | Почему |
| --- | --- | --- |
| Сессия, «чья доска», первый HTML | Сервер (RSC, Actions, `getBoard`) | Секреты и права не едут в браузер |
| Колонки и карточки после гидратации | TanStack Query | Серверные данные с кэшем, откатом и refetch |
| Карточка, которую только что добавили/правили/удалили | `useOptimistic` поверх Query | Формы + Actions, UI не ждёт сеть |
| Карточка, которую сейчас тащат | Локальный `useState` | Жест не должен спорить с refetch |
| Ошибка формы / ИИ | Инлайн в колонке или карточке | URL не засоряем, карточку не теряем |

Намеренно нет второго «источника правды» в Zustand. Когда появится сайдбар или фильтры — туда, не в копию доски.

## Что сознательно не взяли в этом шаге

| Не взяли | Почему сейчас |
| --- | --- |
| Zustand | Нечем кормить, кроме жеста DnD — а жест живёт в `useState` |
| React Hook Form | Формы простые: одно-два поля и Zod; RHF — когда вырастут |
| shadcn/ui | Сначала поведение канбана; «красивый UI» без работающего порядка — декорация |
| Query на список досок | RSC + Actions хватает; кэш Query там не окупается |
| Тесты, axe, Playwright | Это месяц 3 |
| Drag колонок | Сначала инвариант карточек |
| Redis / лимит ИИ в базе | Потолок 3–7 пунктов в схеме; rate limit — месяц 5 |

## Что осталось шероховатым (честно)

- Стрим ИИ до модели в одной из сессий упирался в Gateway (таймаут, потом проверка аккаунта). Код готов: ключ на сервере, 503 без ключа, клиент не ходит на api.openai.com. Чтобы увидеть живой стрим, Gateway должен пустить запрос.
- Параллельные гонки create и clamp позиции в одном из прогонов не гоняли руками — инвариант в схеме и транзакции есть, боевой шторм — позже.
- Колонки create/delete ещё не на `useOptimistic` (их actions в части потоков редиректят). Карточки — да.

---

## Зачем этот месяц в обучении

К концу шага 2 есть не «ещё один туду-лист», а набор историй, которые спрашивают на middle+:

- почему unique `position` и сдвиг в транзакции, а не надежда на UI;
- почему Query и `useOptimistic` рядом, а Zustand для доски не нужен;
- почему ИИ-ключ только на сервере и почему стрим — Route Handler;
- почему Suspense режет водопад, а один `getBoard` лучше десяти запросов.

Дальше по плану — месяц 3: тесты, a11y, производительность. Канбан для этого уже есть на чем гонять сценарии.
